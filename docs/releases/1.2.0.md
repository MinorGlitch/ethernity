# Ethernity 1.2.0

Release preparation: the stable tag and publication are pending. PyPI trusted-publisher setup
is also pending. Check [GitHub Releases](https://github.com/MinorGlitch/ethernity/releases)
for available downloads.

Ethernity 1.2 adds backup updates, a guided terminal app with an optional local browser mode,
new print layouts, and easier installation and recovery text entry.

## Updating from an older version

- Ethernity 1.2 continues to recover backups and recovery sheets from stable 1.0 and 1.1 releases.
  Keep those pages; upgrading the application does not require reprinting them.
- New backups and Rebuild output use document v2. Recover them with Ethernity 1.2 or a 1.2
  browser recovery kit. Earlier readers cannot open them or apply updates.
- Updates can extend an unsealed document-v1 or document-v2 backup. Cumulative updates need the
  original and the selected update. Incremental updates need the original and every update
  through the selected version. The original stays unchanged; the update is a separate v2
  document. Sealed backups cannot receive updates.
- Scripts now use `ethernity run ...`. The older `ethernity api` interface and its streamed
  responses have been replaced. Run `ethernity run --help` for commands; `--json` returns one task
  response. Existing automation must adapt to the new commands and response structure.
- Native Intel Mac archives and Homebrew bottles are no longer built. Intel Mac users can use
  the [Python installation route](../install.md#python-users), which is not tested on Intel macOS.

See [format compatibility](../format_history.md) for the complete reader and document matrix.

## Backup updates and recovery

**Manage > Add files** adds new files or replaces existing ones without reprinting the entire
backup. Cumulative updates are the default. Incremental updates can save more paper but require
keeping the complete update sequence.

**Rebuild backup** turns a selected version into a new standalone backup with fresh recovery
sheets. **Replace sheets** creates recovery sheets without changing the backed-up files.
Rebuild keeps the passphrase; neither operation revokes old credentials.

Save the full fingerprint shown after creating a backup or update. It lets recovery check that
you supplied the expected version. Recovery checks the documents you supply; even with a matching
fingerprint, it cannot prove that no newer update exists elsewhere. See
[updates and recovery](../advanced_operations.md).

## Terminal and browser app

Run `ethernity` for the terminal interface or `ethernity --web` for the same app in your browser.
Browser mode runs on your computer, uses local files and settings, and needs no internet access.
Keep the launching terminal open. Closing or refreshing a browser tab ends that tab's session.

Backup, Restore, Recovery Kit, and Settings are available directly in navigation. Result screens
separate the generated-PDF recovery check from the steps for printing and testing physical pages.

## Printed documents and the offline kit

Sentinel, Archive, Forge, Ledger, and Maritime use a shared PDF renderer with bundled fonts.
Print previews and capacity examples help estimate the paper needed for a backup.

The standalone HTML recovery kit remains separate from browser mode and needs no running
Ethernity process. It supports pasted text and an optional camera scanner. Both the app and kit
highlight recovery text and provide whitespace cleanup. Printed dotted line numbers are accepted
without changing the encoded payload; malformed input still fails validation.

Printed kits use compressed application data and denser QR encoding. After the two startup codes,
the assembly page accepts fragments in any order and reports missing or damaged parts. Existing
printed kits keep their own reconstruction instructions. Use a 1.2 kit for new document-v2 backups.

## Installation and distribution

Linux and Windows installers check release checksums, validate the executable, and support
upgrades and removal. Failed replacements restore the previous installation. Portable downloads
include Python, fonts, browser assets, and both recovery kit variants.

Native packages cover Linux x64 and ARM64, macOS Apple silicon, and Windows x64. Linux packages
require glibc 2.35 or newer; Ubuntu 22.04 is the tested minimum. Homebrew bottles cover Apple
silicon macOS and Linux x64. Python installations require Python 3.11 or newer.

Downloads have Sigstore verification bundles. The executables do not have Apple Developer ID
signatures, macOS notarization, or Windows Authenticode signatures.

Stable releases include a WinGet manifest, but community submission and acceptance are separate.
Use the installer or portable ZIP until the package is accepted. PyPI publication also requires
the pending publisher setup. See the [installation guide](../install.md).

## Before storing a backup

Test a restore from the printed pages you plan to keep. A successful check of the original PDFs
does not test the printer or the resulting paper copies.
